🔗 1.2 · Understanding our network

¿Cómo conectamos nuestras máquinas virtuales?

🎯 Objetivo
Diferenciar los principales modos de conexión de red de VirtualBox, seleccionar el más adecuado según las necesidades de comunicación y comprender por qué nuestro escenario combina una Red NAT / NAT y una Red interna.

Ya conocemos las máquinas que formarán nuestro entorno. El siguiente paso es comprender cómo estarán conectadas.

Cuando añadimos una tarjeta de red a una máquina virtual, debemos decidir a qué tipo de red virtual estará conectada. Esta decisión determina con quién podrá comunicarse: Con otras máquinas virtuales, con el equipo anfitrión, con la red física o con el exterior.

💡 Idea principal
Una interfaz como enp0s3 o enp0s8 no es NAT, puente o red interna por sí misma. VirtualBox determina a qué tipo de red está conectada cada tarjeta virtual.

🤔 Primero, pensemos qué necesitamos

Antes de elegir un modo de red debemos preguntarnos qué comunicaciones necesitamos establecer. Observa estas cuatro situaciones:

A · Una VM necesita salir al exterior

Una máquina virtual necesita acceder al exterior, por ejemplo para descargar actualizaciones.

B · Varias VM y salida al exterior

Varias máquinas virtuales necesitan comunicarse entre ellas y disponer de acceso al exterior.

C · Participar en la red física

Queremos que la máquina virtual participe en la red física a la que está conectado el anfitrión.

D · Laboratorio aislado

Varias máquinas virtuales deben comunicarse entre ellas dentro de un entorno virtual aislado.

🌐 Modos de conexión de VirtualBox

VirtualBox dispone de diferentes modos de conexión. Para construir nuestro escenario necesitamos comprender cuatro: NAT, Red NAT, Adaptador puente y Red interna.

1 · NAT

NAT es una forma sencilla de proporcionar acceso al exterior a una máquina virtual. VirtualBox sitúa un motor NAT entre la máquina virtual y la red utilizada por el anfitrión.

🖥️ Máquina virtual → NAT → ☁️ Exterior

Cada máquina configurada de esta forma queda, por defecto, detrás de su propio NAT. Por tanto, varias máquinas con NAT no forman automáticamente una misma red virtual entre ellas.

Recordar:
Una VM necesita una forma sencilla de salir al exterior.
2 · Red NAT · NAT Network

Una Red NAT crea una red virtual compartida. Las máquinas conectadas a ella pueden comunicarse entre sí y disponer, al mismo tiempo, de acceso al exterior.

🖥️ VM 1      🖥️ VM 2      🖥️ VM 3
↓       ↓       ↓
Red NAT
↓
☁️ Exterior
Recordar:
Varias VM pueden compartir una misma red virtual y salir al exterior.
3 · Adaptador puente · Bridged Networking

El modo puente conecta la interfaz virtual con una interfaz física del equipo anfitrión, permitiendo que la máquina virtual participe en la red a la que está conectado el anfitrión.

💻 Máquina virtual → 🖥️ Interfaz del anfitrión → 🏫 Red física
Recordar:
La máquina virtual pasa a participar en la red física a través del equipo anfitrión.
4 · Red interna · Internal Network

Una Red interna crea una red virtual aislada. Las máquinas virtuales conectadas a la misma red interna pueden comunicarse entre ellas.

🖥️ VM 1      🖥️ VM 2      🖥️ VM 3
↓       ↓       ↓
Red interna

Por sí sola, esta red no proporciona acceso al exterior ni a la red física.

Recordar:
Varias VM pueden comunicarse dentro de un laboratorio virtual aislado.

🧭 Comparemos los cuatro modos

Ahora podemos comparar qué necesidad resuelve cada modo antes de decidir cuál utilizar en nuestro escenario.

🧩 Apliquemos lo aprendido a nuestro escenario

Ya conocemos las principales posibilidades que ofrece VirtualBox. Ahora debemos decidir cómo conectar las máquinas de nuestro entorno de despliegue.

No vamos a elegir un modo de red porque resulte más sencillo de configurar. Primero analizaremos qué comunicaciones necesitamos y, a partir de ellas, tomaremos una decisión.

Nuestro entorno necesita...

🖥️ Los servidores Git, Web, FTP y DNS-LDAP y el cliente Linux Mint deben poder comunicarse dentro de nuestro entorno.

🔒 Queremos disponer de un laboratorio virtual aislado de la red física del centro.

🌍 Nuestro entorno necesitará también disponer de conexión con el exterior.

🏫 No queremos conectar directamente cada servidor a la red física del centro.

🤔 ¿Qué elegirías?

Recuerda los cuatro modos que acabamos de analizar:

NAT Red NAT Adaptador puente Red interna

¿Utilizarías un único modo de red o combinarías varios?

Piensa qué opción responde mejor a cada una de las necesidades anteriores.

🔍 Analicemos las necesidades

1 · Necesitamos un laboratorio aislado

Git, Web, FTP, DNS-LDAP y Linux Mint necesitan comunicarse entre sí, pero queremos mantener estas comunicaciones separadas de la red física del centro.

De los modos estudiados, la Red interna responde a esta necesidad: Permite comunicar nuestras máquinas dentro de un entorno virtual aislado.

2 · Pero tenemos un problema...

Una Red interna permite comunicar nuestras máquinas, pero no proporciona por sí sola conexión con el exterior.

Necesitamos, por tanto, una segunda conexión.

3 · Necesitamos conexión con el exterior

Podríamos conectar las máquinas directamente a la red física mediante un adaptador puente, pero nuestro objetivo es mantener el laboratorio independiente de la infraestructura física del centro.

Utilizaremos una Red NAT o NAT como conexión de nuestro escenario con el exterior.

💡 Ya tenemos las dos piezas
🟦 Red interna + 🟧 Red NAT / NAT

Pero todavía tenemos que decidir cómo relacionar ambas redes.

¿Necesitan todos nuestros servidores estar conectados directamente a las dos?

🔧 Nuestra solución

No conectaremos todas las máquinas a las dos redes. Nuestro diseño utilizará el servidor DNS-LDAP como punto de unión entre ambos ámbitos.

Para ello, DNS-LDAP será la única máquina de nuestro escenario que dispondrá de dos interfaces de red.

🟧 Red NAT · Conexión con el exterior

La interfaz enp0s3 del servidor DNS-LDAP estará conectada a una Red NAT / NAT. Esta será la conexión de nuestro escenario con el exterior.

🟦 Red interna · Nuestro laboratorio

Las cinco máquinas compartirán nuestra red interna:

192.168.X.0/24
X = número de rango indicado en el aula

Git, Web, FTP y Linux Mint estarán conectados a esta red. El servidor DNS-LDAP también pertenecerá a ella mediante su segunda interfaz, enp0s8.

🤔 Una nueva pregunta

Ya sabemos que Git, Web, FTP y Linux Mint están en nuestra Red interna y que DNS-LDAP dispone además de una conexión con la Red NAT.

¿Qué camino seguirá una comunicación cuando una máquina de nuestra Red interna necesite alcanzar el exterior?
