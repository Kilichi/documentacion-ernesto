CONFIGURACIÓN BÁSICA DEL SERVIDOR DNS

⚙️ 4. Configuración básica de BIND9

Configuraremos BIND9 para atender las consultas de nuestra Red Interna y utilizar los servidores DNS proporcionados por la conexión NAT como reenviadores.

🎯 Objetivo

Obtener la información de red proporcionada por NAT y utilizarla para configurar BIND9, permitiendo las consultas procedentes de nuestra Red Interna y el reenvío de las consultas DNS hacia los servidores utilizados por la conexión exterior.

4.1. Obtener la información proporcionada por NAT

Antes de modificar BIND9 necesitamos conocer cómo está accediendo actualmente nuestro servidor DNS-LDAP al exterior.

El adaptador configurado como NAT en VirtualBox proporciona automáticamente al servidor información necesaria para comunicarse con otras redes y resolver nombres.

Vamos a identificar esa información antes de configurar BIND9.

🔎 Paso 1 · Identifica la salida hacia el exterior

Consulta la tabla de enrutamiento del servidor:

ip route

Localiza la línea correspondiente a la ruta por defecto. A partir de ella debes ser capaz de identificar:

Puerta de enlace: __________________________________

Interfaz utilizada para salir: __________________________________

🔎 Paso 2 · Identifica los servidores DNS

Consulta ahora la información que utiliza el sistema para la resolución de nombres:

resolvectl

Si necesitas visualizar la información de forma más detallada, utiliza:

resolvectl status

Localiza la información correspondiente a la interfaz conectada mediante NAT y anota los servidores DNS asociados a ella.

Interfaz NAT: __________________________________

Servidor/es DNS: __________________________________

🧠 Interpreta la información antes de continuar

La puerta de enlace obtenida con ip route y los servidores DNS mostrados por resolvectl no tienen la misma función.

Para configurar los reenviadores de BIND9 utilizaremos los servidores DNS asociados a la conexión NAT que acabas de identificar.

4.2. Configurar named.conf.options

Una vez obtenida la información necesaria, vamos a configurar las opciones básicas de BIND9.

El fichero que modificaremos es:

/etc/bind/named.conf.options

Ábrelo con el editor de texto que utilices habitualmente:

Con vim 
sudo vim /etc/bind/named.conf.options
Con nano 
sudo nano /etc/bind/named.conf.options

4.3. Interfaces de escucha · listen-on

La directiva listen-on indica en qué interfaces IPv4 aceptará BIND9 consultas DNS.

Configura:

listen-on { any; };
💡 ¿Qué significa?

any permite que BIND9 escuche en las interfaces IPv4 disponibles en el servidor, incluida la interfaz conectada a nuestra Red Interna.

4.4. Equipos autorizados · allow-query

Debemos indicar qué equipos pueden enviar consultas a nuestro servidor DNS.

Permitiremos las consultas procedentes del propio servidor y de nuestra Red Interna:

allow-query {
    localhost;
    192.168.x.0/24;
};
📌 Recuerda

Sustituye x por el tercer octeto asignado a tu infraestructura.

4.5. Configurar los reenviadores · forwarders

Cuando BIND9 reciba una consulta sobre un nombre externo que necesite resolver, utilizará los servidores definidos como reenviadores.

Para configurar estos reenviadores utilizaremos la información que hemos obtenido previamente mediante resolvectl.

Sustituye el valor indicado por el servidor DNS asociado a tu conexión NAT:

forwarders {
    DIRECCIÓN_DNS_OBTENIDA;
};

Si tu conexión proporciona más de un servidor DNS, puedes indicar varios reenviadores:

forwarders {
    DIRECCIÓN_DNS_1;
    DIRECCIÓN_DNS_2;
};

⚠️ No utilices un DNS elegido manualmente

En esta práctica no debes configurar directamente servidores DNS públicos conocidos, como 8.8.8.8.

Debes utilizar la información obtenida de la configuración NAT de tu servidor. El objetivo no es copiar una dirección que sabemos que funciona, sino identificar e interpretar la configuración real del sistema.

Información Cómo obtenerla Utilidad
Puerta de enlace ip route Identificar la salida hacia otras redes
Interfaz de salida ip route Identificar la interfaz conectada mediante NAT
Servidores DNS resolvectl Configurar los forwarders de BIND9

4.6. Revisa la configuración

Una vez incorporados los valores correspondientes a tu entorno, la parte relevante de named.conf.options tendrá una estructura equivalente a la siguiente:

options {

    listen-on { any; };

    allow-query {
        localhost;
        192.168.x.0/24;
    };

    forwarders {
        DIRECCIÓN_DNS_OBTENIDA;
    };

};
📌 Atención

El bloque anterior muestra la estructura que necesitamos. Debes adaptar tanto la red 192.168.x.0/24 como el reenviador a los datos correspondientes a tu propia infraestructura.

4.7. Configurar BIND9 para utilizar IPv4

Nuestro entorno de prácticas está configurado para trabajar con IPv4. Por ello, configuraremos BIND9 para utilizar únicamente este protocolo.

Edita el fichero:

Con vim 
sudo vim /etc/default/named
Con nano 
sudo nano /etc/default/named

Añade la opción -4 a las opciones de ejecución de BIND9.

📌 Antes de modificar

Comprueba el contenido actual del fichero y mantén las opciones que ya existan. El objetivo es añadir el funcionamiento mediante IPv4, no sustituir innecesariamente el resto de la configuración.

4.8. Validar la configuración

Antes de aplicar los cambios debemos comprobar que la configuración de BIND9 no contiene errores de sintaxis.

sudo named-checkconf
✅ Configuración correcta

Si no existen errores de sintaxis, el comando finalizará sin mostrar mensajes. Si aparece algún error, no reinicies BIND9 todavía: localízalo y corrígelo primero.

4.9. Aplicar los cambios

Una vez validada correctamente la configuración, reinicia BIND9:

sudo systemctl restart bind9

A continuación, comprueba que el servicio continúa funcionando:

sudo systemctl status bind9

El servicio deberá aparecer como activo.

✅ Comprobación de BIND9

Antes de continuar, verifica que has completado correctamente todo el proceso:

☐ He identificado la puerta de enlace mediante ip route.

☐ He identificado la interfaz conectada mediante NAT.

☐ He identificado los servidores DNS mediante resolvectl.

☐ He configurado listen-on.

☐ He autorizado mi Red Interna mediante allow-query.

☐ He utilizado como forwarders los DNS obtenidos de la configuración NAT.

☐ He configurado BIND9 para trabajar mediante IPv4.

☐ named-checkconf no muestra errores.

☐ Después de aplicar los cambios, systemctl status bind9 muestra el servicio activo.

📁 Portfolio

Documenta la configuración realizada. Las evidencias deben permitir comprobar cómo has obtenido la información necesaria, no únicamente mostrar el resultado final.

Incluye la información relevante obtenida con ip route y resolvectl, identifica el reenviador seleccionado y conserva evidencias de la validación de la configuración y del estado final de BIND9.
