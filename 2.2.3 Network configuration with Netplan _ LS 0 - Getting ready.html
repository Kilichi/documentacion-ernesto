2.2.3 Network configuration with Netplan

⚙️ 2.2.3 · Network configuration with Netplan

Llevamos nuestro plan de direccionamiento a Ubuntu Server

🎯 Objetivo
Recuperar el procedimiento para configurar una dirección IPv4 estática en Ubuntu Server mediante Netplan, interpretar la estructura básica de sus archivos YAML, aplicar los cambios y comprobar que la configuración obtenida coincide con nuestro plan de direccionamiento.
🔗 Continuamos desde 2.2.2

Ya has preparado tu propio plan de direccionamiento. Conoces la red 192.168.X.0/24, la dirección correspondiente a cada máquina y la puerta de enlace que utilizarán nuestros servidores internos.

Ahora necesitamos convertir ese diseño en una configuración real de Ubuntu Server.

🗂️ 1 · Meet Netplan

Ubuntu Server utiliza Netplan para describir la configuración de sus interfaces de red.

Esta configuración se almacena en archivos de texto con extensión .yaml dentro del directorio:

/etc/netplan/

El nombre concreto del archivo puede variar según la instalación. Por eso, antes de modificar nada, debemos comprobar qué archivo existe realmente en nuestra máquina.

🔍 2 · Find your configuration

Comienza observando el contenido del directorio:

$ ls /etc/netplan/

Podrías encontrar, por ejemplo, un archivo como:

50-cloud-init.yaml
⚠️ No memorices el nombre

No debes asumir que el archivo siempre se llama 50-cloud-init.yaml. Comprueba primero el contenido de /etc/netplan/ y trabaja con el archivo existente en tu sistema.

👀 3 · Inspect before changing

Antes de editar una configuración debemos conocer su estado actual.

Si tu archivo es 50-cloud-init.yaml, puedes consultar su contenido mediante:

$ sudo cat /etc/netplan/50-cloud-init.yaml

Una configuración inicial podría presentar una estructura similar a:

network:
  ethernets:
    enp0s3:
      dhcp4: true
  version: 2

En este ejemplo estamos definiendo la interfaz enp0s3 y permitiendo que obtenga su configuración IPv4 mediante DHCP.

🧱 4 · Understanding YAML

Los archivos de Netplan utilizan YAML. Su estructura depende de la indentación: los espacios indican qué elementos se encuentran dentro de otros.

⚠️ El espaciado importa

Una configuración puede contener los valores correctos y, aun así, no ser válida si su estructura YAML está mal el espaciado.

Mantén un espaciado coherente utilizando espacios.

✏️ 5 · Edit the configuration

Una vez localizado el archivo de Netplan, necesitamos editarlo para sustituir la configuración automática por nuestro direccionamiento estático.

Como se trata de un archivo de configuración del sistema situado en /etc, necesitaremos privilegios administrativos para modificarlo.

⌨️ Option 1 · vim

Podemos editar el archivo utilizando vim:

$ sudo vi /etc/netplan/50-cloud-init.yaml

Recuerda algunas operaciones básicas:

Acción vim
Comenzar a editar i
Salir del modo de inserción Esc
Guardar y salir :wq + Enter
Salir sin guardar :q! + Enter
📝 Option 2 · nano

También podemos utilizar el editor nano:

$ sudo nano /etc/netplan/50-cloud-init.yaml

Algunas operaciones básicas:

Acción nano
Editar Escribir directamente
Guardar Ctrl + O y Enter
Salir Ctrl + X
🛡️ ¿Por qué utilizamos sudo?

Tanto si utilizamos vim como nano, estamos modificando un archivo de configuración del sistema ubicado en /etc. Es una tarea administrativa, por lo que necesitamos los privilegios adecuados.

💡 Elige tu herramienta

vim y nano son dos editores diferentes. El resultado de la configuración no depende del editor utilizado, sino de que el contenido del archivo YAML sea correcto.

📌 6 · Configure a static IPv4 address

Nuestros servidores deben conservar las direcciones definidas en el plan de direccionamiento. Por ello utilizaremos direcciones IPv4 estáticas.

Supongamos que estamos configurando el servidor Web de un alumno cuyo rango es X = 200.

Web
Interfaz: enp0s3
IPv4: 192.168.200.154/24
Gateway: 192.168.200.253

Una configuración básica sería:

network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: false
      addresses:
        - 192.168.200.154/24
      routes:
        - to: default
          via: 192.168.200.253

🧠 7 · Read the configuration

No queremos copiar una configuración sin entenderla. Vamos a interpretar sus elementos.

Elemento Función
version: 2 Indica la versión del formato de configuración de Netplan.
ethernets Agrupa las interfaces Ethernet que vamos a configurar.
enp0s3 Es la interfaz sobre la que aplicamos la configuración.
dhcp4: false Evita obtener automáticamente la configuración IPv4 mediante DHCP.
addresses Define la dirección IPv4 y su prefijo.
routes Define las rutas que utilizará el sistema.
to: default Define la ruta utilizada cuando el destino no pertenece a una ruta más específica.
via: 192.168.35.253 Indica la puerta de enlace por la que se enviará ese tráfico.
💡 ¿Y gateway4?

En configuraciones antiguas puedes encontrar gateway4. En nuestro entorno utilizaremos routes para definir la ruta predeterminada.

routes:
  - to: default
    via: 192.168.35.253
⏳ What about DNS?

Netplan también permite definir servidores DNS mediante nameservers.

Todavía no vamos a configurarlos. Nuestra máquina DNS-LDAP aún no presta ese servicio. Lo incorporaremos cuando corresponda dentro de nuestro entorno de despliegue.

🧪 8 · Validate and apply the configuration

Una vez editado y guardado el archivo de Netplan, no debemos aplicar inmediatamente los cambios. Primero comprobaremos que Netplan puede procesar correctamente la configuración que hemos escrito.

🧪 8.1 · Check the configuration

Antes de aplicar la nueva configuración ejecutamos:

$ sudo netplan generate

Este comando procesa los archivos YAML de Netplan y genera la configuración que utilizará posteriormente el sistema. Si detecta determinados errores en el archivo, mostrará información que nos permitirá localizar el problema.

✅ No aparecen errores

Si netplan generate finaliza sin mostrar errores, podemos continuar y aplicar la configuración.

⚠️ Aparece un error

No continúes con netplan apply. Lee el mensaje mostrado por Netplan, vuelve al archivo YAML y localiza el problema.

Corrige la configuración utilizando vim o nano, guarda los cambios y vuelve a ejecutar:

$ sudo netplan generate

Repite el proceso hasta que la configuración pueda procesarse correctamente.

▶️ 8.2 · Apply the configuration

Cuando la comprobación anterior ha finalizado correctamente, podemos aplicar la nueva configuración de red.

$ sudo netplan apply

Netplan aplicará la configuración definida en nuestros archivos YAML a las interfaces correspondientes.

⚠️ Aplicar no significa verificar

Que netplan apply termine sin mostrar errores no demuestra que hayamos introducido los valores que realmente necesita nuestra máquina.

El siguiente paso será comprobar la configuración real del sistema.

🔍 9 · Verify the configuration

Ya hemos validado nuestro archivo con netplan generate y aplicado los cambios mediante netplan apply. Ahora debemos comprobar que la configuración real del sistema coincide con nuestro plan de direccionamiento.

💡 Aplicar no es verificar

Que Netplan haya aplicado la configuración sin mostrar errores no significa necesariamente que hayamos introducido los valores correctos. Debemos comprobar qué configuración está utilizando realmente el sistema.

🌐 9.1 · Check the interface configuration

Comenzaremos comprobando la configuración IPv4 de la interfaz que acabamos de modificar.

Podemos consultar todas las interfaces mediante:

$ ip addr

O consultar directamente la interfaz que nos interesa:

$ ip addr show enp0s3

Si estamos configurando el servidor Web, debemos localizar su dirección IPv4 y comprobar que coincide con nuestro plan:

inet 192.168.X.154/24
🔍 Comprueba:
  • Que estás observando la interfaz enp0s3.
  • Que aparece la dirección 192.168.X.154.
  • Que utiliza el prefijo /24.
  • Que X corresponde al rango que tienes asignado.

🚪 9.2 · Check the routing table

La dirección IPv4 no es el único elemento que hemos configurado. En Netplan también hemos definido una ruta predeterminada para permitir que la máquina pueda enviar tráfico destinado a otras redes.

Para consultar la tabla de rutas ejecutamos:

$ ip route

Si utilizamos como ejemplo un alumno con X = 35, en el servidor Web podríamos obtener una salida similar a:

default via 192.168.200.253 dev enp0s3
192.168.35.0/24 dev enp0s3 proto kernel scope link src 192.168.200.154

No queremos limitarnos a ejecutar el comando. Debemos ser capaces de interpretar su resultado.

Información Significado En nuestro escenario
default Ruta utilizada cuando no existe otra ruta más específica. Permite enviar tráfico destinado a otras redes.
via 192.168.X.253 Dirección de la puerta de enlace. Debe corresponder a la interfaz interna de DNS-LDAP.
dev enp0s3 Interfaz utilizada para alcanzar ese destino. Web utiliza su interfaz conectada a la Red interna.
192.168.X.0/24 Ruta hacia la red directamente conectada. Debe coincidir con nuestra Red interna.
src 192.168.X.154 Dirección de origen asociada a esa ruta. Debe coincidir con la dirección IPv4 de Web.
🔍 Comprueba:
  • Que existe una ruta predeterminada.
  • Que la puerta de enlace es 192.168.X.253.
  • Que utiliza la interfaz enp0s3.
  • Que aparece una ruta hacia 192.168.X.0/24.
  • Que la dirección de origen coincide con la dirección asignada al servidor Web.

🧩 9.3 · Compare plan and reality

Para finalizar, compara la configuración que habías planificado con la que realmente está utilizando el sistema.

Elemento Nuestro plan ¿Cómo lo comprobamos?
Interfaz enp0s3 ip addr show enp0s3
IPv4 192.168.X.154 ip addr show enp0s3
Prefijo /24 ip addr show enp0s3
Red 192.168.X.0/24 ip route
Gateway 192.168.X.253 ip route
✅ Configuration verified

La configuración estará verificada cuando podamos demostrar que la interfaz, dirección IPv4, prefijo, red y puerta de enlace coinciden con los valores definidos en nuestro plan de direccionamiento.

💡 Configuration ≠ Connectivity

Hemos demostrado que nuestra máquina tiene la configuración que habíamos planificado, pero todavía no hemos demostrado que pueda comunicarse correctamente con otras máquinas.

Esa será nuestra siguiente tarea en 2.2.4 · Network diagnostics.

  • sudo netplan apply aplica los cambios.
