🌐 2.2.2 · IPv4 addressing

Recuperamos cómo interpretar el direccionamiento de nuestra red

🎯 Objetivo
Recordar cómo se estructura una dirección IPv4, interpretar una máscara o prefijo de red, identificar la dirección de red y determinar si dos máquinas pertenecen a la misma red y pueden comunicarse directamente.
🔗 Continuamos desde 2.2.1

Ya sabemos identificar nuestras interfaces mediante ip link e ip addr. En la salida de este último comando encontramos información como:

inet 192.168.200.104/24

Ahora necesitamos comprender qué significa realmente.

🔢 1 · Reading an IPv4 address

Una dirección IPv4 está formada por 32 bits, organizados en cuatro grupos de 8 bits llamados octetos.

Normalmente la representamos en notación decimal:

192
.
168
.
200
.
104

Cada octeto puede representar valores comprendidos entre 0 y 255.

🧩 2 · Our addressing scheme

En nuestro entorno de despliegue utilizaremos el siguiente patrón:

192.168.X.0/24
X · Tu rango

X corresponde exclusivamente al tercer octeto y es el número de rango asignado en el aula.

Último octeto · La máquina

En nuestra red, el último octeto nos permitirá diferenciar las distintas máquinas.

🧠 Ejemplo

Si el rango asignado a un alumno es X = 200:

Red → 192.168.200.0/24

🎭 3 · Network mask

Una dirección IP por sí sola no es suficiente para saber a qué red pertenece una máquina. Necesitamos también una máscara de red.

En nuestro escenario utilizaremos:

Máscara
255.255.255.0
=
Prefijo
/24

El prefijo /24 indica que los primeros 24 bits identifican la parte de red. En este caso corresponden a los tres primeros octetos.

🧱 4 · Network and host

Con una red /24 podemos visualizarlo de forma sencilla:

192.168.200
NETWORK
.104
HOST

Todas las máquinas de nuestra red compartirán los tres primeros octetos y tendrán un valor diferente en el último.

🏠 5 · Network address

La dirección de red identifica a la propia red, no a una máquina concreta.

192.168.200.0/24
⚠️ Importante

En esta red, 192.168.35.0 identifica la red y no debe asignarse a una de nuestras máquinas.

📢 6 · Broadcast address

Una red IPv4 también dispone de una dirección de broadcast, utilizada para dirigirse al conjunto de equipos de la red mediante broadcast.

Para nuestra red de ejemplo:

192.168.200.255

Por tanto, tampoco utilizaremos esta dirección como dirección individual de una máquina.

🖥️ 7 · Host addresses

Para una red 192.168.200.0/24 tendremos:

Elemento Dirección
Dirección de red 192.168.200.0
Direcciones de host utilizables 192.168.200.1 – 192.168.200.254
Broadcast 192.168.200.255

🔗 8 · Are they on the same network?

Una de las preguntas más importantes que debemos poder responder es si dos máquinas pertenecen a la misma red.

Observa estas dos direcciones:

Caso A
Web → 192.168.200.154/24
Git → 192.168.200.104/24

Ambos pertenecen a 192.168.200.0/24. Por tanto, están en la misma red.

Caso B
Web → 192.168.200.154/24
Equipo B → 192.168.240.104/24

El primero pertenece a 192.168.200.0/24 y el segundo a 192.168.240.0/24. Están en redes diferentes.

🚪 9 · Default gateway

Si el destino está dentro de nuestra misma red, podemos comunicarnos con él directamente a través de la red local.

Si queremos alcanzar un destino que pertenece a otra red, necesitamos enviar el tráfico hacia una máquina capaz de encaminarnos fuera de nuestra red: La puerta de enlace predeterminada o default gateway.

🔗 En nuestro escenario

La interfaz interna de DNS-LDAP tendrá:

192.168.X.253/24

Esta dirección será la puerta de enlace que utilizarán las máquinas de nuestra red interna cuando necesiten alcanzar otras redes.

🖥️ 10 · Our deployment environment

Ahora podemos interpretar completamente nuestro esquema de direccionamiento:

Máquina IPv4 Red
DNS-LDAP 192.168.X.253/24 192.168.X.0/24
Git 192.168.X.104/24 192.168.X.0/24
Web 192.168.X.154/24 192.168.X.0/24
FTP 192.168.X.204/24 192.168.X.0/24
Linux Mint 192.168.X.Y/24 192.168.X.0/24
📌 X and Y
  • X = número de rango asignado en el aula. Aparece exclusivamente en el tercer octeto.
  • Y = valor válido y libre del último octeto elegido para Linux Mint.
🔍 Check it

Supongamos que tu rango es X = 200. Sin ejecutar ningún comando, responde:

  1. ¿Cuál es la dirección de red?
  2. ¿Cuál es la máscara en notación decimal?
  3. ¿Cuál es el prefijo?
  4. ¿Cuál es la dirección de broadcast?
  5. ¿Qué rango de direcciones puede utilizarse para hosts?
  6. ¿Qué dirección tendrá el servidor Web?
  7. ¿Qué dirección utilizarán las máquinas como puerta de enlace?
🧩 Mini challenge · Build your addressing plan

Ha llegado el momento de transformar el esquema general 192.168.X.0/24 en tu propio plan de direccionamiento.

📌 Utiliza tu rango

Sustituye X por el número de rango que tienes asignado en el aula.

Para Linux Mint tendrás que elegir además un valor Y válido y que no produzca ningún conflicto con las direcciones ya utilizadas.

Prepara el direccionamiento de tu red indicando:

  1. La dirección de tu red.
  2. Su máscara en notación decimal y en formato CIDR.
  3. La dirección de broadcast.
  4. El rango de direcciones disponibles para hosts.
  5. La dirección IPv4 que tendrá cada máquina.
  6. El valor Y que has elegido para Linux Mint.
  7. La dirección que utilizarán las máquinas internas como puerta de enlace.

🔍 Antes de terminar

Comprueba que todas las máquinas pertenecen a tu misma red, que ninguna dirección está repetida y que no has utilizado ni la dirección de red ni la dirección de broadcast para identificar una máquina.

🧠 What should you remember?

  • Una dirección IPv4 tiene 32 bits organizados en cuatro octetos.
  • La máscara permite determinar qué parte identifica la red.
  • /24 equivale a 255.255.255.0.
  • La dirección de red identifica la red, no una máquina.
  • La dirección de broadcast tampoco se asigna a un host.
  • La máscara permite determinar si dos direcciones pertenecen a la misma red.
  • Para alcanzar otras redes necesitamos una puerta de enlace.
