🔀 5. Configuración del servidor como router

Permitiremos que los equipos de nuestra Red Interna puedan acceder al exterior a través del servidor DNS-LDAP.

🎯 Objetivo

Configurar el servidor DNS-LDAP para que actúe como router y puerta de enlace de nuestra Red Interna, reenviando hacia el exterior el tráfico generado por sus equipos.

5.1. ¿Por qué necesitamos enrutamiento?

Los equipos de nuestra Red Interna de VirtualBox pueden comunicarse entre sí, pero esta red está aislada y no dispone directamente de acceso a Internet.

El servidor DNS-LDAP, en cambio, dispone de dos interfaces: una conectada a la Red Interna y otra con acceso al exterior. Por ello puede actuar como punto de unión entre ambas redes.

📌 Importante

Configurar una puerta de enlace en los clientes no es suficiente. El servidor DNS-LDAP debe estar preparado para reenviar paquetes entre sus interfaces.

5.2. Activar IP forwarding

De forma predeterminada, nuestro servidor no debe actuar como router entre sus interfaces. Para permitir el reenvío de paquetes IPv4, debemos activar IP forwarding.

Edita el fichero:

Con vim 
sudo vim /etc/sysctl.conf
Con nano 
sudo nano /etc/sysctl.conf

Localiza la siguiente configuración y asegúrate de que queda activa:

net.ipv4.ip_forward=1

Guarda los cambios y aplícalos:

sudo sysctl -p

Comprueba que el reenvío IPv4 está activo:

sysctl net.ipv4.ip_forward
✅ Resultado esperado 
net.ipv4.ip_forward = 1

5.3. Configurar NAT/MASQUERADE

Los equipos de la Red Interna utilizan direcciones privadas 192.168.x.0/24. Para que su tráfico pueda salir al exterior utilizaremos NAT.

Antes de crear la regla, identifica el nombre de la interfaz del servidor que tiene acceso al exterior:

ip a

En nuestro escenario, si la interfaz hacia el exterior es enp0s3, añade la siguiente regla:

sudo iptables -t nat -A POSTROUTING -o enp0s3 -j MASQUERADE
💡 ¿Qué hace MASQUERADE?

Permite que el tráfico procedente de la Red Interna salga utilizando la dirección IP de la interfaz exterior del servidor DNS-LDAP.

5.4. Permitir el tráfico entre interfaces

Además de activar el reenvío IP y configurar NAT, debemos permitir que iptables reenvíe el tráfico entre las dos interfaces del servidor.

En nuestro escenario:

🌍 enp0s3 → interfaz hacia el exterior.

🖧 enp0s8 → interfaz hacia la Red Interna.

Permite que el tráfico iniciado desde la Red Interna salga hacia el exterior:

sudo iptables -A FORWARD -i enp0s8 -o enp0s3 -j ACCEPT

A continuación, permite el tráfico de respuesta correspondiente a conexiones ya establecidas:

sudo iptables -A FORWARD -i enp0s3 -o enp0s8 -m state --state RELATED,ESTABLISHED -j ACCEPT
⚠️ Comprueba tus interfaces

Los nombres enp0s3 y enp0s8 deben corresponder realmente a las interfaces de tu servidor. No copies las reglas sin comprobarlo previamente con ip a.

5.5. Comprobar las reglas

Antes de hacer persistente la configuración, comprueba las reglas que acabas de añadir.

Reglas de reenvío:

sudo iptables -L FORWARD -n -v

Reglas de NAT:

sudo iptables -t nat -L POSTROUTING -n -v

5.6. Hacer persistente la configuración

Las reglas añadidas con iptables no deben perderse cuando reiniciemos el servidor.

Instala el paquete que permite conservarlas:

sudo apt install iptables-persistent

Durante la instalación, acepta guardar las reglas actuales cuando el sistema lo solicite.

También puedes guardar posteriormente la configuración actual mediante:

sudo netfilter-persistent save
💡 ¿Por qué necesitamos persistencia?

Una infraestructura debe seguir funcionando después de reiniciar. Guardar las reglas evita tener que introducir manualmente la configuración de enrutamiento cada vez que arranque el servidor.

✅ Comprobación del enrutamiento

Antes de comprobar la resolución DNS, vamos a verificar que el enrutamiento funciona independientemente del servicio DNS.

1. Comprueba la puerta de enlace del cliente

ip route

Debe existir una ruta por defecto que utilice el servidor DNS-LDAP:

default via 192.168.x.253

2. Comprueba la comunicación con DNS-LDAP

ping -c 4 192.168.x.253

3. Comprueba el acceso al exterior mediante una IP

ping -c 4 8.8.8.8

☐ net.ipv4.ip_forward tiene valor 1.

☐ Existe una regla MASQUERADE para la interfaz exterior.

☐ Las reglas FORWARD permiten el tráfico entre las interfaces.

☐ El cliente utiliza 192.168.x.253 como puerta de enlace.

☐ El cliente alcanza 192.168.x.253.

☐ El cliente puede alcanzar una dirección IP externa.

☐ Las reglas se han guardado para que sean persistentes.

🧠 Conectividad ≠ resolución DNS

Si el cliente puede alcanzar una dirección IP externa, hemos demostrado que el enrutamiento funciona. Esto no demuestra todavía que pueda resolver nombres como google.es. Esa comprobación se realizará en el siguiente apartado.
