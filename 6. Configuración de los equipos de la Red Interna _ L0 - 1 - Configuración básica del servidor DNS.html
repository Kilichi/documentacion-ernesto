CONFIGURACIÓN BÁSICA DEL SERVIDOR DNS

💻 6. Configuración de los equipos de la Red Interna

Configuraremos los equipos para utilizar el servidor DNS-LDAP como puerta de enlace y servidor DNS.

🎯 Objetivo

Configurar correctamente los parámetros de red de los equipos conectados a la Red Interna para que utilicen el servidor DNS-LDAP como puerta de enlace y servidor DNS.

6.1. Configuración de red del cliente

Cada equipo de nuestra infraestructura debe disponer de una dirección IP única perteneciente a la Red Interna 192.168.x.0/24.

Además de su dirección IP, debemos configurar dos parámetros fundamentales:

🚪 Puerta de enlace

Permitirá al equipo enviar tráfico destinado a otras redes a través del servidor DNS-LDAP.

192.168.x.253

🌐 Servidor DNS

Todas las consultas DNS del equipo se enviarán a nuestro servidor DNS-LDAP.

192.168.x.253

📌 ¿Qué DNS configuramos en los clientes?

Los equipos de la Red Interna deben utilizar como servidor DNS únicamente el servidor DNS-LDAP.

No configures directamente en los clientes los servidores DNS obtenidos de NAT. Esos servidores ya han sido configurados como reenviadores de BIND9. El cliente pregunta a DNS-LDAP y BIND9 se encarga del resto del proceso.

6.2. Datos de configuración

Antes de modificar ningún fichero, identifica los parámetros correspondientes al equipo que estás configurando.

Parámetro Configuración
Dirección IP Dirección asignada al equipo dentro de 192.168.x.0/24
Prefijo /24
Puerta de enlace 192.168.x.253
Servidor DNS 192.168.x.253
📌 Recuerda

Sustituye x por el tercer octeto asignado a tu infraestructura y utiliza la dirección IP correspondiente al equipo que estés configurando.

6.3. Configurar la red con Netplan

En los servidores Ubuntu de nuestra infraestructura modificaremos la configuración mediante Netplan.

Comprueba primero el nombre del fichero disponible:

ls /etc/netplan/

Abre el fichero correspondiente con tu editor:

Con vim 
sudo vim /etc/netplan/NOMBRE_FICHERO.yaml
Con nano 
sudo nano /etc/netplan/NOMBRE_FICHERO.yaml

Ejemplo de estructura

Adapta la siguiente estructura a la interfaz y dirección IP de tu equipo:

network:
  version: 2
  ethernets:
    INTERFAZ:
      dhcp4: false
      addresses:
        - 192.168.x.IP/24
      routes:
        - to: default
          via: 192.168.x.253
      nameservers:
        addresses:
          - 192.168.x.253

🧠 No copies: adapta la configuración

INTERFAZ debe sustituirse por el nombre real de la interfaz conectada a la Red Interna.

x corresponde al tercer octeto asignado a tu infraestructura.

IP debe sustituirse por la dirección asignada al equipo que estás configurando.

6.4. Validar la configuración

Antes de aplicar cualquier cambio, comprueba que Netplan puede procesar correctamente el fichero:

sudo netplan generate
✅ Si no aparecen errores

La configuración puede ser procesada por Netplan y podemos continuar con su aplicación.

⚠️ Si aparece un error

No apliques todavía la configuración. Revisa especialmente la indentación YAML, el nombre de la interfaz y los parámetros introducidos.

6.5. Aplicar la configuración

Una vez validado el fichero, aplica los cambios:

sudo netplan apply

No des por terminada la configuración únicamente porque el comando haya finalizado. Ahora debemos comprobar el resultado.

6.6. Comprobar la dirección IP

Consulta las interfaces del equipo:

ip a

Localiza la interfaz conectada a la Red Interna y comprueba que dispone de la dirección IP y el prefijo esperados.

6.7. Comprobar la puerta de enlace

Consulta la tabla de enrutamiento:

ip route

Debes encontrar una ruta por defecto que utilice el servidor DNS-LDAP como puerta de enlace.

default via 192.168.x.253

6.8. Comprobar el servidor DNS

Comprueba qué servidor DNS está utilizando el sistema:

resolvectl

En la información correspondiente a la interfaz de la Red Interna debe aparecer nuestro servidor:

192.168.x.253

✅ Comprobación del cliente

Antes de realizar las pruebas de conectividad y resolución DNS, comprueba que la configuración del equipo es correcta:

☐ El equipo tiene la dirección IP que le corresponde.

☐ La máscara o prefijo es /24.

☐ La puerta de enlace es 192.168.x.253.

☐ El servidor DNS configurado es 192.168.x.253.

☐ netplan generate no muestra errores.

☐ La configuración se ha aplicado correctamente.

☐ ip a muestra la dirección esperada.

☐ ip route muestra la ruta por defecto a través del servidor DNS-LDAP.

🧠 Comprende el recorrido

Cliente → DNS-LDAP → DNS proporcionado por NAT

El cliente no necesita conocer los DNS externos. Solo conoce a DNS-LDAP. Cuando sea necesario resolver un nombre externo, BIND9 reenviará la consulta utilizando los servidores DNS que identificamos previamente en la conexión NAT.
