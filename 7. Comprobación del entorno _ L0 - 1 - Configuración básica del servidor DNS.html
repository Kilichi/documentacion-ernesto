🧪 7. Comprobación del entorno

Verificaremos progresivamente la conectividad, el enrutamiento y la resolución DNS de nuestra infraestructura.

🎯 Objetivo

Comprobar de forma ordenada el funcionamiento de la infraestructura y ser capaces de localizar en qué punto se produce un fallo: comunicación con DNS-LDAP, salida hacia Internet o resolución DNS.

🧭 Sigue el recorrido

No realizaremos todas las pruebas al mismo tiempo. Avanzaremos progresivamente y solo continuaremos cuando la comprobación anterior funcione correctamente.

📌 Una prueba cada vez

Si una comprobación falla, detente en ese punto. No tiene sentido diagnosticar la resolución DNS si todavía no existe conectividad con el servidor o acceso al exterior.

7.1. Cliente → DNS-LDAP

Comenzamos comprobando la comunicación más cercana: el cliente debe poder alcanzar el servidor DNS-LDAP dentro de la Red Interna.

Desde uno de los equipos de la Red Interna ejecuta:

ping -c 4 192.168.x.253
✅ Si responde

Existe comunicación entre el cliente y DNS-LDAP a través de la Red Interna. Podemos continuar hacia el exterior.

7.2. DNS-LDAP → Internet

Ahora comprobaremos si el cliente puede alcanzar Internet utilizando DNS-LDAP como router.

Para esta prueba utilizaremos una dirección IP, evitando así que intervenga todavía la resolución DNS.

ping -c 4 8.8.8.8
💡 ¿Qué demuestra esta prueba?

Si obtenemos respuesta, sabemos que el cliente puede alcanzar una red externa utilizando DNS-LDAP como puerta de enlace. Por tanto, el enrutamiento y NAT están funcionando. Esta prueba todavía no demuestra que DNS funcione.

7.3. Comprobar la resolución DNS

Ya sabemos que existe conectividad con el servidor y que podemos alcanzar Internet mediante una dirección IP. Ahora comprobaremos específicamente el servicio DNS.

Desde el cliente consulta directamente a nuestro servidor DNS-LDAP:

nslookup www.google.es 192.168.x.253

También puedes realizar la comprobación con dig, si la herramienta está disponible:

dig @192.168.x.253 www.google.es
✅ Resultado esperado

DNS-LDAP debe recibir la consulta y devolver una respuesta con la información correspondiente al nombre consultado.

7.4. Cliente → Internet mediante nombre

Ahora combinaremos las dos funciones que hemos comprobado por separado: enrutamiento y resolución DNS.

ping -c 4 www.google.es

Antes de fijarte únicamente en las respuestas del ping, observa si el sistema ha sido capaz de transformar el nombre en una dirección IP.

🧠 Interpreta el resultado

Un servidor externo puede no responder a mensajes ICMP y, aun así, la resolución DNS funcionar correctamente. Para evaluar DNS, comprueba primero si el nombre ha sido resuelto a una IP.

7.5. Comprobar BIND9 desde el servidor

Además de comprobar el funcionamiento desde un cliente, verificaremos el servicio directamente en DNS-LDAP.

Comprueba primero que BIND9 continúa activo:

sudo systemctl status bind9

A continuación, realiza una consulta DNS desde el propio servidor:

dig @127.0.0.1 www.google.es
💡 ¿Qué estamos aislando?

Esta prueba permite comprobar BIND9 sin depender de la comunicación entre cliente y servidor. Si funciona localmente pero falla desde un cliente, tendremos que revisar la configuración relacionada con la Red Interna.

7.6. Comprobar BIND9 desde el cliente

Finalmente, comprobaremos que el cliente utiliza realmente DNS-LDAP como servidor DNS, sin indicar manualmente el servidor en la consulta.

Comprueba primero la configuración DNS del cliente:

resolvectl

La interfaz conectada a la Red Interna debe utilizar:

192.168.x.253

Realiza ahora una consulta sin especificar manualmente el servidor:

nslookup www.google.es

Comprueba en el resultado qué servidor ha respondido a la consulta. Debe corresponder a nuestro DNS-LDAP.

✅ Comprobación final

El entorno estará correctamente configurado cuando puedas verificar todos los niveles:

☐ El cliente puede comunicarse con 192.168.x.253.

☐ El cliente puede alcanzar una dirección IP externa.

☐ DNS-LDAP puede resolver un nombre externo.

☐ El cliente puede consultar directamente a DNS-LDAP.

☐ El cliente utiliza 192.168.x.253 como servidor DNS.

☐ El cliente puede resolver nombres sin indicar manualmente un servidor DNS.

☐ El cliente puede acceder al exterior utilizando nombres.

☐ BIND9 permanece activo y sin errores.
