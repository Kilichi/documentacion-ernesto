🔎 1.3 · Follow the connection

¿Qué camino sigue una comunicación?

🎯 Objetivo
Interpretar el recorrido de una comunicación dentro de nuestro escenario, diferenciando entre un destino situado en la misma red y un destino situado fuera de ella, e identificar la función de la puerta de enlace.

Ya sabemos cómo están conectadas nuestras máquinas: Git, Web, FTP, DNS-LDAP y Linux Mint comparten la Red interna 192.168.X.0/24.

También sabemos que DNS-LDAP dispone de una segunda interfaz conectada a la Red NAT / NAT.

Ahora vamos a cambiar nuestra forma de observar la infraestructura. En lugar de preguntarnos «¿cómo están conectadas las máquinas?», seguiremos el recorrido de una comunicación desde su origen hasta su destino.

💡 La primera pregunta

¿El destino está dentro o fuera de mi red?

La respuesta determinará el camino que deberá seguir la comunicación.

🧪 Trabajemos con un ejemplo

Supongamos que a un alumno se le ha asignado X = 200 y ha elegido Y = 200 para su cliente Linux Mint.

Máquina Dirección
DNS-LDAP 192.168.200.253/24
Git 192.168.200.104/24
Web 192.168.200.154/24
FTP 192.168.200.204/24
Linux Mint 192.168.80.200/24

🟦 Caso 1 · El destino está en nuestra red

Desde Linux Mint queremos comunicarnos con el servidor Web.

💻 Linux Mint
192.168.200.200 → 🌐 Web
192.168.200.154

Linux Mint tiene la dirección 192.168.200.200/24 y Web 192.168.200.154/24.

Ambas direcciones pertenecen a la misma red:

192.168.200.0/24
✓ Mismo segmento de red

Como origen y destino pertenecen a la misma red, la comunicación puede realizarse dentro de nuestra Red interna. No necesitamos utilizar la conexión con la Red NAT / NAT.

🌍 Caso 2 · El destino está fuera de nuestra red

Cambiemos ahora la situación. El servidor Web necesita comunicarse con un equipo situado fuera de la red 192.168.200.0/24.

🤔 Tenemos un problema

El destino ya no pertenece a nuestra Red interna. Por tanto, Web no puede tratarlo como otra máquina de 192.168.200.0/24.

¿A quién debe entregar la comunicación para poder alcanzar otras redes?

🚪 La puerta de enlace

Cuando un equipo necesita comunicarse con un destino que no pertenece a su propia red, necesita disponer de una puerta de enlace predeterminada o default gateway.

🚪 Default gateway

Es el equipo de nuestra red al que enviamos las comunicaciones destinadas a otras redes.

🖥️ ¿Quién puede cumplir esa función?

Recordemos el diseño que acabamos de estudiar. Solo una de nuestras máquinas está conectada a las dos redes:

🖥️ DNS-LDAP
192.168.X.253
Red interna + Red NAT

En nuestro escenario utilizaremos la dirección 192.168.X.253 del servidor DNS-LDAP como puerta de enlace de las máquinas de la Red interna.

📌 Importante

La puerta de enlace debe ser una dirección alcanzable desde la propia red. Por eso utilizaremos la interfaz interna de DNS-LDAP: 192.168.X.253.

El servidor Git tiene la dirección 192.168.200.104/24.

📌 Por ahora, solo necesitamos comprenderlo

Todavía no vamos a configurar este comportamiento. Antes necesitamos recuperar algunos conocimientos de Linux y redes que utilizaremos para construir y comprobar nuestro escenario.
