2.1.3 · Ownership and permissions

🔐 2.1.3 · Ownership and permissions

Recuperamos cómo Linux controla el acceso a archivos y directorios

🎯 Objetivo
Recordar cómo Linux utiliza propietarios, grupos y permisos para controlar el acceso a archivos y directorios, interpretar su representación y recuperar los comandos necesarios para modificarlos y comprobar el resultado.

Ya sabemos identificar usuarios y grupos y podemos desplazarnos por el sistema de archivos. Pero todavía necesitamos responder a una pregunta fundamental:

¿Quién puede acceder a un recurso y qué puede hacer con él?

Linux utiliza un sistema de propiedad y permisos para determinar qué usuarios pueden leer, modificar o ejecutar archivos y qué operaciones pueden realizar sobre los directorios.

🔎 ¿Por qué necesitamos recordarlo?

Durante el curso trabajaremos con archivos de configuración, directorios de aplicaciones, contenido web y recursos utilizados por diferentes servicios. Un permiso incorrecto puede impedir que un servicio acceda a los archivos que necesita o permitir un acceso que no debería existir.

🔎 1 · Reading permissions

En el apartado anterior utilizamos ls -l para obtener información detallada sobre los archivos y directorios. Ahora vamos a interpretar parte de esa información.

$ ls -l
-rw-r----- 1 student developers 1240 Sep 28 10:30 server.conf

De esta línea nos interesan especialmente tres elementos:

🔐 Permisos

-rw-r-----

👤 Propietario

student

👥 Grupo

developers

👤 2 · Owner, group and others

Los permisos se organizan en tres conjuntos. Cada uno corresponde a una categoría de usuarios:

Categoría Representación ¿A quién afecta?
Owner u Al usuario propietario del recurso.
Group g A los usuarios a los que se aplican los permisos del grupo propietario.
Others o Al resto de usuarios.

🔑 3 · Read, write and execute

Para cada categoría podemos encontrar tres permisos básicos:

Permiso Símbolo Archivo Directorio
Read r Leer su contenido. Consultar los nombres de sus entradas.
Write w Modificar su contenido. Crear, eliminar o renombrar entradas, cuando los demás permisos y condiciones lo permiten.
Execute x Ejecutarlo cuando se trata de un archivo ejecutable adecuado. Acceder o atravesar el directorio.
💡 Archivo y directorio no significan lo mismo

Los símbolos son los mismos, pero su efecto cambia. El permiso x, por ejemplo, permite ejecutar un archivo, mientras que sobre un directorio permite acceder a él y recorrer su estructura.

🧩 4 · Let's interpret permissions

-   rw-   r--   ---
Bloque Significado
- El recurso es un archivo ordinario.
rw- El propietario puede leer y escribir.
r-- El grupo puede leer.
--- El resto de usuarios no dispone de ninguno de estos permisos.
🔍 Check it

Ejecuta ls -l sobre varios archivos de tu directorio personal e identifica:

  • El tipo de recurso.
  • Los permisos del propietario.
  • Los permisos del grupo.
  • Los permisos del resto de usuarios.
  • El propietario y el grupo propietario.

🛠️ 5 · Changing permissions with chmod

El comando chmod permite modificar los permisos de archivos y directorios.

Una forma de hacerlo es mediante la notación simbólica.

chmod [quién] [operación] [permiso] recurso
¿Quién?
u · owner
g · group
o · others
a · all
¿Qué hacemos?
+ · añadir
- · quitar
= · establecer
¿Qué permiso?
r · read
w · write
x · execute
$ chmod u+x script.sh
$ chmod g+w shared.txt
$ chmod o-r private.txt
$ chmod u=rw,g=r,o= report.txt

🔢 6 · Octal notation

También podemos representar los permisos mediante valores numéricos. Cada permiso tiene asociado un valor:

r = 4
w = 2
x = 1

Sumando estos valores podemos representar cualquier combinación de permisos.

Valor Permisos
0 ---
1 --x
2 -w-
3 -wx
4 r--
5 r-x
6 rw-
7 rwx
🧠 Ejemplo

Queremos establecer:

  • Propietario: rw- → 4 + 2 = 6
  • Grupo: r-- → 4
  • Otros: --- → 0
$ chmod 640 server.conf

👤 7 · Changing ownership

Los permisos no son lo único que podemos modificar. También puede ser necesario cambiar el usuario propietario o el grupo propietario de un recurso.

$ chown USER file
$ chown USER:GROUP file
$ chgrp GROUP file
Comando Función
chown Cambia el propietario y, opcionalmente, el grupo propietario.
chgrp Cambia el grupo propietario.

🎭 8 · Default permissions and umask

Cuando creamos un nuevo archivo o directorio no elegimos manualmente sus permisos cada vez. El sistema parte de unos permisos base y aplica una máscara denominada umask.

Podemos consultar la máscara actual ejecutando:

$ umask
💡 ¿Cómo interpretamos umask?

Como referencia habitual, los permisos base son:

  • Archivos: 666 → rw-rw-rw-
  • Directorios: 777 → rwxrwxrwx

La máscara elimina permisos de esos valores base.

Ejemplo: umask 022

De forma simplificada:

Archivo: 666 → 644 → rw-r--r--
Directorio: 777 → 755 → rwxr-xr-x
🔍 Check it

Cada vez que modifiques permisos o propietarios, comprueba el resultado.

$ ls -l

No basta con ejecutar chmod, chown o chgrp: debes ser capaz de interpretar el resultado.

🧩 Mini challenge · Protect the configuration
🔗 Continuamos con el reto anterior

En 2.1.2 · File system and directories preparaste tu espacio de trabajo ~/daw_lab y creaste varios directorios y archivos.

Ahora vamos a continuar trabajando sobre ese mismo entorno.

Antes de continuar, comprueba que dispones de esta estructura:

~/daw_lab/
├── config/
│   └── server.conf
└── backup/
    └── server.conf

Hasta ahora nos hemos preocupado de crear y organizar los recursos. Ha llegado el momento de controlar quién puede utilizarlos.

Queremos proteger el archivo ~/daw_lab/config/server.conf de forma que:

  • El propietario pueda leerlo y modificarlo.
  • El grupo pueda leerlo.
  • El resto de usuarios no tenga acceso.

Tu tarea:

  1. Localiza server.conf dentro de tu espacio daw_lab.
  2. Comprueba sus permisos actuales.
  3. Determina qué permisos necesita cada categoría.
  4. Exprésalos mediante notación simbólica.
  5. Exprésalos mediante notación octal.
  6. Aplica los permisos necesarios.
  7. Comprueba que el resultado coincide con lo solicitado.
🔍 Antes de terminar

Debes poder justificar por qué la configuración resultante corresponde a rw-r-----, explicar su equivalencia numérica y demostrar que los permisos se han aplicado correctamente.
